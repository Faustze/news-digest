# Skill: task-workflow

Workflow для выполнения задач из TODO → next-task → implementation → commit message → refresh docs.

## Когда использовать

Пользователь говорит: "выполни задачу", "работай по плану", "next task", "сделай следующее", "workflow".

## Порядок действий

### 1. Прочитай `docs/TODO.md`

Если есть незавершённые задачи (`- [ ]`) — выбери одну по приоритету или спроси пользователя, какую.

### 2. Прочитай `docs/next-task.md`

Проверь, есть ли уже активная задача. Если `next-task.md` содержит конкретное ТЗ — работай по нему. Если написано "Активной задачи нет" — перенеси выбранную задачу из TODO в next-task.

### 3. Реализуй

Выполни задачу. Следи за:
- `AGENTS.md` — правила проекта
- `ruff check .` — линтер
- `ruff format .` — форматирование
- `pytest` — тесты

### 4. Спроси пользователя

После реализации **обязательно** спроси:

> Готово. Вот что сделано:
> [краткое описание изменений]
>
> Подходит ли решение? Нужны ли правки?

Жди ответа. **Не коммить без разрешения.**

### 5. Напиши сообщение для коммита

Если пользователь одобрил — напиши **одно** сообщение для коммита в формате:

```
<type>: <краткое описание>

<что изменено (2-3 bullet points)>
```

Где `type`: `feat`, `fix`, `refactor`, `docs`, `test`, `chore`.

**Не коммить сам.** Покажи сообщение и спроси:

> Вот сообщение для коммита:
> ```
> feat: ...
> ```
>
> Коммитить?

### 6. Если пользователь разрешил коммитить

```bash
git add <изменённые файлы>
git commit -m "<сообщение>"
```

### 7. Обнови документацию

После успешного коммита обнови:

**`docs/PLAN.md`** — пометь задачу как выполненную:
- Перенеси из «В работе» / «Бэклог» в «Выполнено»
- Добавь дату и короткое описание

**`docs/next-task.md`** — обнови текущее ТЗ:
- Если есть следующая задача из PLAN — перенеси её в next-task
- Если задач нет — напиши «Активной задачи нет»

**`docs/STATE.md`** — обнови глобальное состояние проекта:
- «Активная задача» — что делается сейчас (или «нет»)
- «Последний коммит» — тип и краткое описание
- «Следующий шаг» — что делать дальше
- «Выполнено» — добавь новую галочку если появилась новая завершённая работа
- «Решения» — обнови если изменился стек или подход

### 8. Готово

Сообщи пользователю что сделано и что обновлено.

## Важные правила

- **Не коммить без явного разрешения пользователя**
- **Не удаляй рабочий код без необходимости**
- **Проверяй ruff и тесты перед предложением коммита**
- **Обновляй PLAN.md, next-task.md и STATE.md после каждого успешного коммита**
- **Спрашивай подтверждение перед каждым коммитом**
- **STATE.md — зеркало текущего состояния: что сделано, что в работе, что дальше**
