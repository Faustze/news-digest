# News Digest — дизайн продукта

## О продукте

Персональный новостной дайджест для одного пользователя.

- **RSS** — агрегация новостей из 50+ источников по 12 категориям
- **AI-классификация** — Groq LLM определяет категорию, подтемы и важность
- **Персонализация** — ранжирование по интересам профиля, исключениям и feedback
- **Telegram** — доставка дайджеста с кнопками обратной связи на каждую новость
- **Web UI** — статический интерфейс для настройки профиля (Nuxt SPA)

Архитектурные ограничения: без backend, без VPS, single-user. Профиль/feedback живут в JSON (`user-profile.json`, `feedback.json`); локальный слой PostgreSQL (Alembic + репозитории) добавлен как инструмент разработки и не является обязательным для пайплайна.

## Web UI

### Принципы

- Один пользователь, без авторизации.
- Всё хранится client-side (localStorage) и переносится через экспорт/импорт `user-profile.json`.
- Интерфейс понятен человеку без технической подготовки — никаких RSS, LLM, API в текстах.

### Онбординг

Последовательный wizard:

1. **Приветствие** — «Начать»
2. **Категории** — выбор из 12 категорий (можно несколько)
3. **Подтемы** — для каждой выбранной категории: 6 подтем с контролем интереса 0–5
4. **Детализация** — коротко / нормально / подробно
5. **Сложность языка** — простые слова / обычный / технический
6. **Время** — 5 / 10 / 20 / 30+ минут
7. **Исключения** — что не показывать (можно пропустить)
8. **Личный контекст** — свободное поле (можно пропустить)

Каждый шаг имеет «Назад» без потери введённых значений; прогресс виден.

### Профиль (страница `/profile`)

- Редактирование категорий и подтем, общих настроек, регионов, исключений, личного контекста.
- Экспорт профиля в JSON, импорт, сброс.
- Импорт не перезаписывает профиль молча: невалидный файл отклоняется с сообщением.

## Схема профиля (`user-profile.json`)

- `version` — версия схемы (миграции при изменении).
- `categories` — 12 категорий; у каждой `enabled: boolean` и `interests` (подтема → 0–5).
  - `0` = явный запрет, `1..5` = растущий интерес. Отсутствующая подтема = нейтрально.
- `general` — `detail_level`, `language_level`, `reading_time`, `frequency`, `priority`, `language`, `source_reliability`, `regions`, `exclusions`, `personal_context`.

## Ранжирование

Приоритет факторов (нельзя переопределить нижним):

1. жёсткие исключения (`exclusions`, `interest=0`)
2. включённая категория
3. интерес к подтемам
4. надёжность источника
5. feedback-сигналы
6. личный контекст (небольшой boost)
7. популярность/важность

Неизвестная категория никогда не попадает в дайджест.

## Обратная связь (Telegram)

- У каждой новости свои кнопки 👍 / 👎 / 🔕.
- Реакция привязана к стабильному ID новости.
- `poll_feedback.py` опрашивает `getUpdates` без webhook; курсор продвигается только после сохранения реакций.

## Пайплайн

fetch → normalize → deduplicate → classify (LLM) → rank → select (по reading-time budget) → summarize → render → Telegram → feedback.

Классификатор явно помечает каждую новость `accepted: true/false`; неклассифицированные новости в дайджест не попадают.
